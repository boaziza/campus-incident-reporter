# Campus Incident Reporter

A Flutter mobile app for ALU students to report campus issues (broken facilities, water shortages, power outages, damaged furniture, sanitation and safety concerns) and track them until they are resolved. Campus staff review reports and update their status.

Built with **Flutter**, **Provider**, **Firebase Authentication**, **Cloud Firestore** and **Firebase Storage**.

## Features

**Students**
- Register and log in with an ALU email only (`@alustudent.com` / `@alueducation.com`). The account must be email-verified before entering the app.
- Report an incident with a category, title, description, campus location and an optional photo (camera or gallery).
- Choose to hide their name from other students (staff still see it).
- Browse every campus report with search plus status and category filters.
- View report details: status timeline, staff notes and the attached photo.
- Confirm "I am affected too" on other students' reports so staff can prioritise.
- Edit or delete their own report while it is still *Submitted*.

**Staff**
- Dashboard with campus-wide totals, open issues by category and a "Needs attention" queue sorted by how many students are affected.
- Update a report's status (Submitted → In Progress → Resolved, or Rejected) with a note for the student.
- Delete spam or abusive reports.

## Project structure

```
lib/
├── main.dart                 # Firebase init, MultiProvider, theme, routes, AuthWrapper
├── firebase_options.dart     # generated by `flutterfire configure`
├── models/                   # Incident, AppUser, StatusUpdate, status & category enums
├── services/                 # Firebase access only (AuthService, IncidentService, StorageService)
├── providers/                # AuthProvider, IncidentProvider (ChangeNotifier)
├── pages/                    # screens
├── components/               # reusable widgets (cards, badges, buttons, sheets)
└── utils/                    # constants, validators, date formatting, route arguments
```

**Layers:** `pages` → `providers` → `services` → Firebase. Screens never call Firebase directly.

## State management (Provider)

- `AuthProvider` listens to `authStateChanges()` and the user's Firestore profile. It exposes `AuthStatus` (`loading`, `unauthenticated`, `unverified`, `authenticated`) and the user's role. `AuthWrapper` in `main.dart` picks the screen from this status.
- `IncidentProvider` keeps one live Firestore stream of incidents. It is a `ChangeNotifierProxyProvider` of `AuthProvider`, so it starts listening on login and clears everything on logout. Search and filters, derived lists (my reports, filtered results, counts) and all create, update and delete actions live here. When staff change a status, every screen updates from the same stream.
- `setState` is used only for local UI state such as form fields, the selected tab or password visibility.

## Firestore data model

```
users/{uid}
  name: string
  email: string
  role: "student" | "staff"
  createdAt: timestamp

incidents/{incidentId}
  title: string
  description: string
  category: "facilities" | "water" | "electricity" | "safety" | "sanitation" | "furniture"
  location: string
  imageUrl: string | null
  imagePath: string | null        # Storage path, used to delete the photo
  status: "submitted" | "inProgress" | "resolved" | "rejected"
  reporterId: string              # users/{uid}
  reporterName: string
  isAnonymous: bool
  upvotes: [uid]                  # "I am affected too"
  statusHistory: [ { status, note, changedBy, changedByName, changedAt } ]
  createdAt: timestamp
  updatedAt: timestamp
```

Photos are stored in Firebase Storage at `incident_images/{uid}/{timestamp}.jpg`.

## Access control

Rules are in [`firestore.rules`](firestore.rules) and [`storage.rules`](storage.rules).

- Only signed-in, email-verified ALU accounts can read or write incidents.
- A new user document must have `role: "student"`, so nobody can make themselves staff, and users can never change their own role.
- Only staff can change `status` and `statusHistory`.
- Reporters can edit the text of their report only while it is `submitted`.
- Other students can add or remove only their own uid in `upvotes`.
- Photo uploads must be images under 5 MB, written into the uploader's own folder.

The app also hides staff-only actions in the UI, but the rules are what actually enforce access.

## Setup

1. Install Flutter (3.x) and the Firebase CLI, then log in: `firebase login`.
2. Install FlutterFire CLI: `dart pub global activate flutterfire_cli`.
3. Create a Firebase project and enable:
   - **Authentication** → Email/Password
   - **Cloud Firestore**
   - **Storage**
4. In the project root run:
   ```bash
   flutterfire configure
   ```
   This replaces the placeholder `lib/firebase_options.dart` and adds `google-services.json` / `GoogleService-Info.plist`.
5. Deploy the security rules:
   ```bash
   firebase deploy --only firestore:rules,storage
   ```
6. Run on an emulator or device:
   ```bash
   flutter pub get
   flutter run
   ```

### Creating a staff account

1. Register in the app with an `@alueducation.com` (or ALU) email and verify it.
2. In the Firebase Console → Firestore → `users/{uid}`, change `role` from `student` to `staff`.
3. The app switches to the staff dashboard right away, because the profile is a live stream.
